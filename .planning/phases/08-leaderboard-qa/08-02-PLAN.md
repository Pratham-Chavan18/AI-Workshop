# Plan 08-02: Integration & E2E Test Suite for Full Campaign Loop

## Goal
Implement automated integration test suite using Vitest + Supertest that validates the complete viral campaign loop end-to-end: registration → referral code → friend registration via referral → credit attributed → leaderboard updated. Includes edge case tests for anti-abuse, rate limiting, and admin security.

- `backend/vitest.config.ts`

- `backend/src/tests/leaderboard.test.ts`
- `backend/src/tests/admin.test.ts`
- `backend/src/tests/helpers/testDb.ts` — test database helpers

<task id="08-02-02">
<title>Registration and referral attribution integration tests</title>
<action>
Create `backend/src/tests/registration.test.ts` using Supertest against Express app:

```typescript
import request from 'supertest'
import { app } from '../app'
import { makeTestRegistration, TEST_CAMPAIGN_ID, TEST_COLLEGE_ID } from './helpers/testDb'
```

Test cases:
1. **Valid registration returns 201 with referral code**:
   - POST /api/v1/registrations with valid body
   - Assert: `status === 201`, `body.success === true`, `body.user.referralCode` matches `/^[A-Z2-9]{6}$/`, `body.user.referralUrl` contains `/register?ref=`
   - Assert response does NOT contain `email` or `phone`

2. **Duplicate email returns 409**:
   - Register same email twice
   - Second request: `status === 409`, `body.error.code === 'EMAIL_ALREADY_REGISTERED'`

3. **Missing required fields return 400 VALIDATION_ERROR**:
   - POST with missing `email` → 400 + `VALIDATION_ERROR`
   - POST with invalid email format → 400 + `VALIDATION_ERROR`

4. **Invalid college UUID returns 400**:
   - POST with `collegeId: 'not-a-uuid'` → 400

Create `backend/src/tests/referral.test.ts`:

1. **Complete referral loop**: Register A → get referralCode → Register B using A's code → Check DB: `Referral` record exists with `referrerUserId === A.id` AND `referredUserId === B.id` AND `status === 'valid'`

2. **Self-referral is rejected**: Register A → Register A again with own code (different email) → Referral table: 0 records. Registration still returns 201.

3. **Double attribution prevented**: Register A → Register B via A's code → Manually re-submit same referred registration attempt → Check: still only 1 Referral record

4. **GET /users/:userId/referrals returns correct stats**:
   - Register A, B via A's code
   - GET /api/v1/users/A.id/referrals → `referralCount === 1`, `goal === 3`, `campusRank >= 1`
</action>

<task id="08-02-03">
<title>Leaderboard privacy and admin security tests</title>
<action>
Create `backend/src/tests/leaderboard.test.ts`:

1. **Campus leaderboard returns campuses ordered by registrations DESC**:
   - Register 3 students at College A, 1 at College B
   - GET /api/v1/leaderboard/campuses → `items[0].collegeName === 'College A'`, `items[0].registrations === 3`

2. **Leaderboard never exposes email or phone**:
   - GET /api/v1/leaderboard/campuses → assert none of `items` have `email` or `phone` keys
   - GET /api/v1/leaderboard/referrers → assert none of `items` have `email` or `phone` keys

3. **Deterministic tie-breaking**:
   - Register 1 student at College A and 1 at College B (both equal count)
   - GET /api/v1/leaderboard/campuses → verify consistent ordering by college name ASC

Create `backend/src/tests/admin.test.ts`:

1. **Admin stats without key returns 401**:
   - GET /api/v1/admin/campaigns/:id/stats → `status === 401`, `body.error.code === 'UNAUTHORIZED'`

2. **Admin stats with wrong key returns 403**:
   - GET with `X-Admin-Key: wrong-key` → `status === 403`, `body.error.code === 'FORBIDDEN'`

3. **Admin stats with correct key returns campaign data**:
   - GET with correct key → `status === 200`, `body.registrations >= 0`, `body.target === 500`

4. **Admin export CSV format**:
   - GET /api/v1/admin/campaigns/:id/export with correct key
   - `status === 200`, `Content-Type` contains `text/csv`
   - Response body first line is CSV header containing `fullName`, `email`, `referralCode`

Update `backend/package.json` scripts:
